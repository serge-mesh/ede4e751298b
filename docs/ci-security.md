# CI security

## Code scanning

`.github/workflows/codeql.yml` analyzes Rust, JavaScript/TypeScript (the UI, browser extension
and scripts), and GitHub Actions with CodeQL's `security-extended` queries. It runs on every
pull request, pushes to `main`, weekly, and manual dispatch. Results appear under
**Security → Code scanning** and on pull requests. Weekly runs start after the workflow is
merged into the default branch.

All three languages use `build-mode: none`: analysis does not require installing application
dependencies or executing project build scripts. Rust code generated by build scripts may
therefore be absent from the scan. The existing Rust build, clippy and test jobs still run
in `ci.yml`, along with `cargo deny` for RustSec advisories, licenses, bans and sources.

The CodeQL job alone receives `security-events: write`; other jobs use `contents: read`.
Workflows use `pull_request`, which supports CodeQL uploads for Dependabot and fork PRs
without repository secrets. Actions are pinned to commit SHAs, checkout does not retain Git
credentials, and Dependabot maintains those pins.

## Dependency updates and review

`.github/dependabot.yml` checks weekly for updates to:

- GitHub Actions in `.github/workflows`.
- The root Cargo workspace and all independent `fuzz/*` workspaces and lockfiles.
- The npm manifests and lockfiles in `ui` and `extension`.
- The Debian base image in `dist/docker/Dockerfile`.

Cargo and npm minor/patch version updates are grouped; major updates remain separate.
Security updates use separate groups when enabled in repository settings. The weekly schedule
and five-PR limit apply to version updates; security updates are driven by alerts and have a
separate GitHub limit. Updates are reviewed and merged through the usual CI process.

When updating `@playwright/test`, update the Playwright container tag and digest in `ci.yml`
in the same PR. `extension/test/ci.test.ts` rejects a mismatch. Dependabot's npm update may
need that companion image change before it passes CI.

`.github/workflows/dependency-review.yml` fails PR checks when a dependency change introduces
a known high or critical vulnerability, including development dependencies. Its report goes
to the job summary without requiring PR-comment write permissions. This checks the PR's
dependency delta; Dependabot alerts and `cargo deny` cover existing vulnerable dependencies.
License enforcement remains in `cargo deny`.

## Repository settings

Workflow files and `dependabot.yml` cannot enable repository-level security settings. An
administrator should verify these under **Settings → Security → Advanced Security** (called
**Code security and analysis** in some GitHub interfaces):

1. Enable the dependency graph, Dependabot alerts and Dependabot security updates. The graph
   also supplies the dependency review check. Dependabot version updates activate when this
   configuration is merged into the default branch.
2. Use CodeQL **advanced setup** with this workflow. If default setup is already enabled,
   disable it before using this workflow to avoid conflicting analysis uploads.
3. After the first runs, add `Review dependency changes` and all three `Analyze (...)` checks
   to the `main` branch ruleset if merges must wait for security jobs. CodeQL alerts are
   reported separately from job success; use a code-scanning merge-protection rule to block
   merges based on alert severity.

These features are available for this public GitHub repository. A move to a private repository
may require GitHub Code Security for code scanning and dependency review.
